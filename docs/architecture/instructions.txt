# 7. Application Logging

This is one of the most important requirements.

The backend must produce **structured JSON logs to stdout**.

Do not write logs primarily to files.

Kubernetes/container runtime should capture stdout/stderr.

Example:

```json
{
  "timestamp": "2026-08-22T10:30:21.421Z",
  "level": "INFO",
  "service": "trade-sentinel-backend",
  "event": "request_completed",
  "method": "POST",
  "path": "/live-trade",
  "status_code": 200,
  "latency_ms": 42,
  "request_id": "..."
}
```

Error example:

```json
{
  "timestamp": "2026-08-22T10:30:23.421Z",
  "level": "ERROR",
  "service": "trade-sentinel-backend",
  "event": "database_error",
  "error_type": "connection_timeout",
  "message": "database request timed out"
}
```

Generate logs for:

```text
request received
request completed
request failed
database query
database error
CSV processing
feature processing
model processing
validation failure
dependency failure
startup
shutdown
health check
```

# 9. Prometheus Metrics

Add a Prometheus `/metrics` endpoint to the backend.

Expose application-level metrics.

At minimum:

### HTTP

```text
http_requests_total

http_errors_total
```

### Application

```text
trade_analysis_total

csv_upload_total
csv_processing_errors_total

live_trade_total
live_trade_errors_total
```

### Database

```text
database_queries_total
database_errors_total
database_query_duration_seconds
database_connections
```

### Model

```text
model_predictions_total
model_prediction_errors_total
model_prediction_duration_seconds
```

Do not expose unbounded labels.

Avoid labels such as:

```text
transaction_id
request_id
user_id
```

because they can create enormous Prometheus cardinality.

Use bounded labels such as:

```text
method
route
status
operation
```
